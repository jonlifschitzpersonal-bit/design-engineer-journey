# Design Engineer Journey — contexto del proyecto

Repo del curso de Jonathan (product designer → design engineer). Las skills de `.claude/skills/` son **generales y reutilizables**; acá está lo que es propio de este repo y de su archivo de Figma.

## Tutoría
- Al empezar cada sesión, leé `PROGRESO.md` y `PLAN-DE-ESTUDIO.md`. Hablá en español rioplatense (vos).
- **Antes de preparar o tocar nada, explicale a Jonathan la clase:** de qué se trata, para qué le sirve, qué va a ver y qué va a hacer. Recién después se arma el material, se lee Figma o se escribe código.
- **Sin preguntas ni ejercicios para responder** (tampoco "explicame con tus palabras"). Todo se muestra resuelto; la práctica es hacer algo donde corresponde (Figma, el repo, DevTools) y Claude lo revisa. Si la clase es solo de lectura, la práctica es otro ejemplo resuelto.
- Si aplicás una regla de las skills que Jonathan todavía no vio en clase, explicala en una línea simple.
- Lo técnico lo decide Claude y lo explica; a Jonathan se le preguntan solo decisiones de producto.
- **Impeccable** (impeccable.style) se usa en todas las clases de UI desde la 5.6: qué comando va en cada clase y sus reglas están en `PLAN-DE-ESTUDIO.md` §4. Lo que propone y es producto lo decide Jonathan; lo que cambia el estilo pasa por tokens, primero en Figma.
- Al cerrar cada clase: progreso + bitácora, reglas nuevas a las skills (escritas en forma general; lo específico de este repo va acá), commit en inglés y push.
- **Si la clase tocó el dashboard:** actualizar también [`DASHBOARD-GURISES-UNIDOS.md`](DASHBOARD-GURISES-UNIDOS.md) (qué se hizo, por qué, archivos nuevos y preguntas de entrevista) y, en el repo del dashboard, `docs/CURRENT_STATE.md` y `docs/PENDING_TASKS.md`. Jonathan lo usa para explicar el proyecto.

## Código
- **Stack desde el módulo 5:** Next.js + React + **Tailwind v4**, con los tokens de Figma en `@theme` y solo los colores del sistema. Es la decisión de este repo, no de las skills. `proyectos/00-seccion-resumen` queda en HTML y CSS (es de la 2.6).
- **Proyecto del dashboard y del sistema:** el dashboard de **Gurises Unidos** (ONG uruguaya, informes a donantes; datos ficticios), fuera de este repo, en `D:\Escritorio\proyectos\gurises-unidos-dashboard`, con su propio repo público (https://github.com/jonlifschitzpersonal-bit/gurises-unidos-dashboard). Creado en la 5.1 con `create-next-app@16.4.3` (TypeScript, App Router, sin `src/`, alias `@/*`, ESLint). La explicación completa para Jonathan (qué es, por qué, cada archivo) está en [`DASHBOARD-GURISES-UNIDOS.md`](DASHBOARD-GURISES-UNIDOS.md). Sus reglas, contexto, estado y decisiones están en su `CLAUDE.md` y su `docs/` (5.3): leelos antes de tocarlo y actualizá `docs/CURRENT_STATE.md` y `docs/PENDING_TASKS.md` al cerrar cada slice. Las sesiones se abren desde la carpeta del curso (para leer el progreso) y se trabaja sobre esa ruta. Su commit, push y PRs van en su repo, no en este. **Sin PRs desde el cierre de la 5.6** (pedido de Jonathan; antes, PRs #19 a #32): Claude trabaja en `main` y pushea directo cada slice cerrado, con lint, build y la verificación en verde. El commit que termina un issue lleva `Closes #N` y el ledger, y el ledger también se le muestra a Jonathan. El ruleset "Protect main" sigue bloqueando el force push y el borrado de `main`. Un PR solo si Jonathan lo pide. El backlog está en sus GitHub Issues, y el flujo, en su `CLAUDE.md`. Antes de cerrar un cambio: `npm run lint` y `npm run build`. **Los tokens se generan desde Figma** (6.1, ADR 0007): Figma Console MCP exporta a `tokens/figma/` y `npm run tokens` (Style Dictionary) escribe `app/tokens.css` y `app/tokens/tokens.ts`. No se editan a mano: el paso a paso está en el `CLAUDE.md` del dashboard. `/tokens` es solo para desarrollo: la referencia pública va a Storybook (decisión de Jonathan, issue #35).
- **Entorno (Windows):** npm global actualizado a 11.19.1 (había un npm 6 en `AppData\Roaming\npm` que le ganaba al de Node y fallaba con `cb() never called`). PowerShell con `ExecutionPolicy RemoteSigned` para el usuario, porque si no, bloquea `npm.ps1` y `npx.ps1`. GitHub CLI (`gh` 2.103.3) instalado desde el zip oficial en `C:\Users\Jony\AppData\Local\Programs\GitHubCLI\bin` (no hay `winget` en este Windows) y autenticado como `jonlifschitzpersonal-bit`; si una sesión no lo encuentra en el PATH, se usa la ruta completa. Al llamarlo desde Bash, pasale `</dev/null`: si espera una respuesta, la sesión se cuelga.
- **Hook de Impeccable (5.6):** el plugin está instalado a nivel usuario (versión en `~/.claude/plugins/cache/impeccable/`), pero su hook ignora los archivos de fuera de la carpeta donde se abrió la sesión, y el dashboard está en otra. Por eso este repo tiene un puente (`.claude/settings.json` + `.claude/hooks/impeccable-dashboard.py`, aprobado por Jonathan): reenvía cada evento a Impeccable como si la sesión estuviera en el dashboard, y solo para archivos de ahí. Toma la última versión instalada sola. Si el dashboard cambia de ruta, se actualiza `DASHBOARD` en el script.
- **Breakpoints:** los de Tailwind (`sm` 640, `md` 768, `lg` 1024, `xl` 1280).
- **Tokens en código:** mismos nombres que en Figma, con las barras pasadas a guiones (`color/text/muted` → `--color-text-muted`). En CSS sin Tailwind, `space/8` → `--space-8`; con Tailwind, el espaciado es su escala (`space/8` → `p-8`, `space/1-5` → `p-1.5`). Las clases de color repiten palabras (`text-text-muted`, `bg-bg-surface`) y quedan así: el nombre es el mismo de Figma a la clase (decidido en la 5.2).
- **Proyectos publicados:** `proyectos/` guarda solo los ejercicios del curso (cada uno con su propio proyecto de Vercel y su Root Directory). Los proyectos de portfolio van en `D:\Escritorio\proyectos\`, cada uno con su repo.
